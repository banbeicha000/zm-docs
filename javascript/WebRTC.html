WebRTC（Web 实时通信）是一个可以用在视频聊天、音频聊天或 P2P 文件分享等 Web 应用中的 API。 ​

WebRTC 主要由以下几个部分组成： ​

  1. getUserMedia() 获取设备的摄像头与（或）麦克风权限，并将这些信号接入 RTC 连接。
  2. RTCPeerConnection用于配置音频或视频聊天的接口。
  3. RTCDataChannel 用于设置两个浏览器之间的端到端数据连接。

MediaDevices.getUserMedia() ​

Details

MediaDevices.getUserMedia() 会提示用户给予使用媒体输入的许可，媒体输入会产生一个MediaStream，里面包含了请求的媒体类型的轨道。此流可以包含一个视频轨道（来自硬件或者虚拟视频源，比如相机、视频采集设备和屏幕共享服务等等）、一个音频轨道（同样来自硬件或虚拟音频源，比如麦克风、A/D 转换器等等），也可能是其他轨道类型

js
navigator.mediaDevices
  .getUserMedia(constraints)
  .then(function (stream) {
    /* 使用这个 stream stream */
  })
  .catch(function (err) {
    /* 处理 error */
  })

constraints 参数是一个包含了 video 和 audio 两个成员的 MediaStreamConstraints 对象，用于说明请求的媒体类型。必须至少一个类型或者两个同时可以被指定。

js
{ audio: true, video: true }
js
if (!navigator.mediaDevices?.enumerateDevices) {
    console.log("enumerateDevices() not supported.")
} else {
    // List cameras and microphones.
    navigator.mediaDevices
        .enumerateDevices()
        .then((devices) => {
            let audioSource = null
            let videoSource = null

            devices.forEach((device) => {
                if (device.kind === "audioinput") {
                    audioSource = device.deviceId
                } else if (device.kind === "videoinput") {
                    videoSource = device.deviceId
                }
            })
            sourceSelected(audioSource, videoSource)
        })
        .catch((err) => {
            console.error(`${err.name}: ${err.message}`)
        })
}

async function sourceSelected(audioSource, videoSource) {
    const constraints = {
        audio: { deviceId: audioSource },
        video: { deviceId: videoSource },
    }
    const stream = await navigator.mediaDevices.getUserMedia(constraints)
    console.log(stream)
    const video = document.querySelector("video")
    video.srcObject = stream
    video.onloadedmetadata = () => {
        video.play()
    }
}

MediaDevices.getDisplayMedia() ​

Details

这个 MediaDevices 接口的 getDisplayMedia() 方法提示用户去选择和授权捕获展示的内容或部分内容（如一个窗口）在一个MediaStream 里。然后，这个媒体流可以通过使用 MediaStream Recording API 被记录或者作为WebRTC 会话的一部分被传输

html
<h1>WebRTC Screenshot</h1>
<button onclick="captureScreenshot()">Capture Screenshot</button>

js
async function captureScreenshot() {
    try {
        // 获取屏幕或窗口的视频流
        const stream = await navigator.mediaDevices.getDisplayMedia({
            video: { cursor: "always" }
        })

        // 创建一个视频元素来加载视频流
        const video = document.createElement("video")
        video.srcObject = stream

        // 等待视频流加载完毕
        await new Promise((resolve) => (video.onloadedmetadata = resolve))

        // 设置视频宽高
        video.width = video.videoWidth
        video.height = video.videoHeight
        video.play()

        // 创建 canvas 并将视频当前帧绘制到 canvas
        const canvas = document.createElement("canvas")
        canvas.width = video.videoWidth
        canvas.height = video.videoHeight
        const ctx = canvas.getContext("2d")
        ctx.drawImage(video, 0, 0, canvas.width, canvas.height)

        // 停止视频流，释放资源
        stream.getTracks().forEach(track => track.stop())

        // 将 canvas 转换为图片并下载
        canvas.toBlob((blob) => {
            const link = document.createElement("a")
            link.href = URL.createObjectURL(blob)
            link.download = "screenshot.png"
            link.click()
            URL.revokeObjectURL(link.href) // 释放 URL 对象
        })
    } catch (err) {
        console.error("Error capturing screenshot:", err)
    }
}

let captureCanvas, captureCtx, selectionCanvas, selectionCtx
let startX, startY, endX, endY, isSelecting = false
let videoStream

async function startCapture() {
    try {
        // 获取屏幕共享流
        videoStream = await navigator.mediaDevices.getDisplayMedia({ video: true })

        // 创建视频元素加载视频流
        const video = document.createElement("video")
        video.srcObject = videoStream

        video.onloadedmetadata = () => {
            // 设置画布大小为屏幕分辨率
            const screenWidth = video.videoWidth
            const screenHeight = video.videoHeight

            // 获取浏览器窗口的可视区域
            const viewportWidth = window.innerWidth
            const viewportHeight = window.innerHeight

            // 设置 captureCanvas 和 selectionCanvas 的大小
            captureCanvas = document.getElementById("captureCanvas")
            captureCanvas.width = viewportWidth
            captureCanvas.height = viewportHeight
            captureCtx = captureCanvas.getContext("2d")

            selectionCanvas = document.getElementById("selectionCanvas")
            selectionCanvas.width = viewportWidth
            selectionCanvas.height = viewportHeight
            selectionCtx = selectionCanvas.getContext("2d")

            // 将视频帧绘制到 captureCanvas 上，仅绘制浏览器窗口可视区域
            video.play()
            captureCtx.drawImage(
                video,  // 视频源
                0, 0, viewportWidth, viewportHeight,  // 裁剪坐标
                0, 0, viewportWidth, viewportHeight   // canvas 坐标
            )

            // 停止屏幕共享以防止画面抖动，并释放资源
            videoStream.getTracks().forEach(track => track.stop())

            // 显示蒙层
            document.getElementById("overlay").style.display = "flex"

            // 添加鼠标事件处理框选区域
            captureCanvas.addEventListener("mousedown", startSelection)
            captureCanvas.addEventListener("mousemove", updateSelection)
            captureCanvas.addEventListener("mouseup", endSelection)
        }

    } catch (err) {
        console.error("Error capturing screen:", err)
    }
}

// 开始框选
function startSelection(e) {
    isSelecting = true
    startX = e.offsetX
    startY = e.offsetY
    selectionCtx.clearRect(0, 0, selectionCanvas.width, selectionCanvas.height)
}

// 更新框选区域
function updateSelection(e) {
    if (!isSelecting) return

    endX = e.offsetX
    endY = e.offsetY

    selectionCtx.clearRect(0, 0, selectionCanvas.width, selectionCanvas.height)
    selectionCtx.strokeStyle = "red"
    selectionCtx.lineWidth = 2
    selectionCtx.strokeRect(startX, startY, endX - startX, endY - startY)
}

// 结束框选
function endSelection() {
    isSelecting = false
}

// 下载选中区域
function downloadSelection() {
    const width = Math.abs(endX - startX)
    const height = Math.abs(endY - startY)

    // 处理框选区域
    const selectionCanvas = document.createElement("canvas")
    selectionCanvas.width = width
    selectionCanvas.height = height
    const selectionCtx = selectionCanvas.getContext("2d")

    selectionCtx.drawImage(
        captureCanvas,
        Math.min(startX, endX),
        Math.min(startY, endY),
        width,
        height,
        0,
        0,
        width,
        height
    )

    // 下载选中区域
    selectionCanvas.toBlob((blob) => {
        const link = document.createElement("a")
        link.href = URL.createObjectURL(blob)
        link.download = "selection.png"
        link.click()
        URL.revokeObjectURL(link.href)
    })
}

截图应用 getDisplayMedia ​

在前端开发中，实现网页截图是一项常见的需求，从用户反馈、错误监控到内容分享，应用场景广泛。目前主流的实现方式主要有三类，它们在原理、性能和适用场景上有着天大的差别。本文将深入剖析 npm 包 @zumer/snapdom、浏览器原生API MediaDevices.getDisplayMedia()（如 js-web-screen-shot 库所用）以及经典的 html2canvas 库。

一、核心原理对比 ​

这三者的实现思路截然不同，可以形象地比喻为 “设计图复刻”、“真实拍照” 和 “手工绘画”。

1. @zumer/snapdom：设计图复刻 (DOM → SVG foreignObject) ​

@zumer/snapdom 采用了一种非常精巧的方案，它将DOM节点转换为一个自包含的SVG图像。

  • DOM克隆与分析：首先，它深度克隆目标DOM元素，并遍历每个节点，使用 window.getComputedStyle() 获取最终应用的CSS样式。
  • 资源内联：接着，它会通过 fetch 获取页面中的所有外部资源（如 <img> 图片、background-image 背景图、@font-face 字体），并将它们转换为Base64 Data URI格式，直接嵌入到克隆体或CSS样式中。这是确保SVG能独立显示的关键。
  • SVG foreignObject 封装：这是它的核心技术。它不尝试将每个<div>都翻译成SVG的<rect>，而是创建了一个SVG <foreignObject> 元素。这个强大的标签允许在SVG内部嵌入任意的HTML内容。它将处理好的HTML克隆体和所有CSS样式一并放入 <foreignObject> 中。
  • 输出：最终，整个包含 <foreignObject> 的SVG被序列化为一个Data URI字符串，从而得到一个矢量的、可无限缩放的截图结果。

2. js-web-screen-shot：真实拍照 (getDisplayMedia) ​

这种方式利用了现代浏览器提供的原生屏幕捕获API，实现真正的“所见即所得”截图。

  • 请求用户授权：代码调用 navigator.mediaDevices.getDisplayMedia()，浏览器会弹出一个原生UI对话框，强制要求用户手动选择要分享的屏幕、窗口或标签页。此步骤无法通过代码绕过。
  • 获取媒体流：用户授权后，API返回一个包含屏幕实时画面的 MediaStream 对象（类似视频流）。
  • 捕获单帧：通过将这个 MediaStream 播放到一个隐藏的 <video> 元素中，然后使用 canvas.getContext('2d').drawImage(video, ...) 将视频的当前帧绘制到Canvas上，从而捕获一帧静态画面。
  • 输出：最后，从Canvas导出位图图片（PNG/JPEG）。

3. html2canvas：手工绘画 (DOM → Canvas重绘) ​

html2canvas 是该领域的经典库，它的工作方式最为“艰苦”。

  • DOM克隆与分析：与 snapdom 类似，它也需要遍历DOM并计算样式。
  • 资源内联：同样需要下载并内联所有外部资源。
  • Canvas重绘 (核心)：这是它与前两者最大的不同。它会模拟浏览器的渲染引擎，在JavaScript层面，将每一个DOM元素和其样式翻译成Canvas的绘图指令。例如，一个<div>会被翻译成 ctx.fillRect()，文本会被翻译成 ctx.fillText()。这是一个纯粹的、繁重的CPU计算过程。
  • 输出：当所有元素都在Canvas上“画”完后，导出最终的位图图片。

三、速度对比分析 ​

速度是选择技术方案的重要考量，我们从用户感知和实际计算两个角度来看。

方案速度排名 (从快到慢)性能瓶颈分析
getDisplayMedia🥇 最快用户交互是唯一的“慢”点。一旦用户确认，底层图形API的执行速度极快，几乎不耗费JS计算资源。
@zumer/snapdom🥈 中等瓶颈在网络。DOM解析相对较快，但等待所有图片和字体通过网络fetch完成是主要耗时。网络好或有缓存时会很快。
html2canvas🥉 最慢CPU和网络双重瓶颈。它不仅要承受snapdom一样的网络请求延迟，还要承担繁重的CPU密集型Canvas重绘计算。

四、结论与适用场景 ​

选择哪种技术，完全取决于你的需求：

  • 追求极致精准、由用户主动发起的截图功能：

    选择 getDisplayMedia。例如，在线协作工具的屏幕分享、需要高保真度的用户反馈截图工具。它的优点是真实、准确，缺点是必须用户交互。

  • 需要自动化、无感知的截图，并期望高质量、可缩放的输出：

    选择 @zumer/snapdom。例如，自动生成文章预览图、前端错误监控中的页面快照回放、生成可编辑的报告。它的优点是自动化、输出矢量图，缺点是受CORS限制。

  • 传统的自动化截图需求，且对渲染小瑕疵不敏感：

    选择 html2canvas。作为老牌库，社区成熟，但在性能和准确度上已不如新方案。当snapdom的foreignObject方案因某些浏览器兼容性问题无法使用时，可作为备选。

总的来说，@zumer/snapdom 凭借其巧妙的 foreignObject 方案，在自动化截图中实现了性能和质量的绝佳平衡，而 getDisplayMedia 则在“真实性”上无可替代。
